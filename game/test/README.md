### 3. `_layout.js` — 배치는 눈으로 봐야 합니다

```bash
node test/_layout.js layout.json
```

진짜 `fit()` 을 기기 5종 × 시스템 3종으로 돌려 **모든 버튼의 좌표를 뽑고**,
겹치거나 화면 밖으로 나가는 것이 있는지 봅니다.
가짜 DOM 검사는 좌표를 비교하지 않으므로 **이걸로만 보이는 버그가 있습니다** —
실제로 게임 중에 우측 존이 게임 화면을 20px 덮고 있는 것을 이걸로 찾았습니다.

뽑은 좌표를 파이썬(PIL)으로 그려서 눈으로 보면 더 확실합니다.
★ 단, 무엇 하나라도 **못 재면 예외를 던지게** 되어 있습니다.
   (한 번은 아무것도 못 재면서 "겹침 없음" 이라고 착각했습니다.)

## 검사를 쓸 때 조심할 것

- **부정형 단언을 조심하세요.** "…안 뜸 / …없음 / ===null" 같은 단언은
  기능이 통째로 죽어도 통과합니다. 반드시 "무엇이 실제로 일어났는가" 를
  하나는 끼워 넣으세요.
- **가짜가 진짜와 어긋나면** 그 검사는 아무것도 안 봅니다.
  `fake.js` 의 `_get_file_data_ptr` 이 `p` 를 그대로 돌려주던 것이 그 예입니다
  (진짜는 껍데기와 속이 다른 주소입니다).

  돌아와 통과합니다. (인계서 8장의 "5프레임/5줄" 사고와 같은 함정)
